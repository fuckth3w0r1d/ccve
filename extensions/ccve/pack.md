把已经验证过的利用链打包成可对外提交的仓库。下面所有路径都相对本仓库根目录。

`work/<target>/` 里是挖掘过程，读 `journal.md` 与 `notes/` 拿最终结论。

## 一、产出位置

新建 `pocs/<target>/`，从 `templates/poc/` 复制骨架：

```
README.md            一段话概述 + 怎么跑 + 目录说明
docs/report.md       完整分析，中文
docs/report-en.md    英文
poc-<distro>/        Dockerfile、docker-compose.yml、target-init.sh、run.sh、exp/
img/                 复现截图
```

`poc-<distro>/` 一个发行版一份，按目标实际情况调整，不必照抄骨架。

## 二、report

开头一段话概述，之后四个板块，中英逐节对应：

| 板块 | 内容 |
| --- | --- |
| 漏洞成因 | 根因所在的代码位置与解释，按缺陷分小节，附触发路径 |
| 影响 | 受影响的软件版本范围，各发行版实际打包的版本状态 |
| 利用分析 | 攻击者能拿到什么，利用链怎么走 |
| 修复建议 | 上游的修复方式，或者应该怎么改 |

## 三、复现环境

每个 `poc-<distro>/` 自包含：`run.sh` 一条命令建镜像、起服务、跑利用、回读容器内结果，退出时清理。`CMD` 环境变量可替换在目标容器内执行的命令。

复现环境从发行版官方源装包，不自行编译。

## 四、验收

在干净环境里跑通：

- 重建镜像后 `run.sh` 连续两次都成功。
- 攻击者只需要能连上端口。
- 另一台机器照 README 能复现。

达标后 `board.md` 该目标状态改 `done`，`漏洞` 列填 CVE 编号或漏洞类型。
